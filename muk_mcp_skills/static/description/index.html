What a skill is

What your AI could not know

The MCP server gives an AI client tools: search, read, write. A skill tells it how your team uses them, in which order, with which wording, and where to stop and ask.

Name and description

The name is what a user can call it by. The description is what the client matches a request against.

Plain instructions

Markdown, the way you would explain it to a new colleague. No code and nothing to deploy.

Files next to it

Attach a tone guide, a checklist or a template. The client reads a file when the instructions send it there.

Groups decide who gets it

A skill limited to accountants is not listed, not found and not readable for anyone else.

Every version is verified

Each file is listed with its size and digest, so a client notices a change and can ask before it uses the new version.

Off without deleting

Archive a skill and it is no longer served. Restore it and it is back with its files and groups.

In the client

Ask, and the right skill loads

Ask in your own words and the client picks the skill whose description fits, or call it by its name. It reads the instructions and their files from Odoo and works through them with the tools of the MCP server.

Every tool call lands in the audit log, like any other call over MCP.

Writing a skill

Explain it like to a colleague

Say what the skill does and when to use it, then list the steps. Name the tools and models where it matters, and say what must never happen without asking.

Keep the instructions short and move the rest into files. A file is mentioned by its name and read only when a step needs it.

Checked when it is saved

A name, description or file the format does not allow is rejected on save, so a skill never goes missing without a reason.

Where it stops

Instructions, not permissions

A skill tells the client what to do. What it may do stays with Odoo and with the client.

Rights still apply

Every step runs as the user behind the key. A skill reaches nothing that user could not, and a read-only key stays read-only.

The client has its say

A client may ask before it loads a skill, and ask again once the skill has changed. Loading a skill is never a permission to run its steps.

It needs a current client

Skills need the current revision of the protocol and a client with the Skills extension. Any other client keeps using the tools as before.

What it adds

One button, where the pager already is

Nothing new to find. It sits in the control panel next to the arrows you already use, and a second click on it is all auto refresh takes.

Click to reload

One click fetches the current page again. The view flashes, the records change, nothing else moves.

Double-click for auto

Lists and kanban views reload on a timer, with a countdown next to the button. The choice is kept per view.

Quiet in the background

A hidden tab stops polling altogether, so a dashboard left open overnight is not asking for data all night.

Reload Views action

A new server action type for automation rules, so a record change can refresh the people looking at it.

Settings  ›  Automation Rules  ›  Actions
Reload Views is an action type like any other, and View Types narrows it to the views you mean.
From the backend

Refresh everyone, from a rule

Pick the model, pick the trigger, add a Reload Views action. When the rule fires, the request travels over the bus and every internal user with that model open sees the new state. No polling, no reloading the page.

Only the views that match

Leave View Types empty for all of them, or name the ones you want. A burst of changes is throttled to one reload.

Requirements

Odoo.sh or on-premise, Community or Enterprise.

Configuration

The interval is the system parameter muk_web_refresh.pager_autoload_interval, in milliseconds. It defaults to 30000.

Installation

Depends on web, bus and base_automation, nothing external.

Usage

Click the button left of the pager to reload once, double-click it on a list or kanban for auto refresh.

Upgrade

The auto refresh choice lives in the browser, so an upgrade has nothing to migrate.

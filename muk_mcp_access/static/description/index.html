What it controls

A second gate in front of the database

The MCP server already runs every call with the rights of the key's user. The allowlist narrows that further, for agents only: the same user keeps everything in the web client.

Hidden, not only refused

The model listing returns only what you allowed, so an agent does not go looking for the rest.

Writes where you want them

Create, update, delete and method calls need the write switch; a read-only model refuses them, even for a read and write key.

A record domain per model

Built in Odoo's domain editor, it can use the user and the companies of the call, and applies to every search and every record id.

Every way in

Reads, writes, exports, printed reports, method calls and the files behind a record go through the same check.

Several models at once

Add Models takes a whole selection with the same permissions, and leaves out the models already listed.

Off without uninstalling

Archive an entry to pause it. With no active entry left, the server is open again, exactly as before.

What the agent meets

A clear answer, not an empty one

A call to a model that is not listed comes back as an error that names the model, so the agent can tell the user what it may not do instead of guessing. The call is logged as an error in the audit log.

The MCP Playground shows it before any client is connected: pick a tool, name a model and try it with a key of your own.

Record domains

Like a record rule, for agents only

Open an entry and add conditions in the domain editor. Searches get the domain added, a record outside it is refused, and a method that returns one is rolled back.

The domain may use user, company_id and company_ids, so one entry follows whoever owns the key and the companies the call runs in.

Checked when it is saved

A domain that does not fit its model is rejected on save, so a typo never becomes a silently empty answer.

Where it stops

It narrows, it never widens

The allowlist sits on top of what the MCP server and Odoo already enforce, and never grants anything they refuse.

Rights still apply

A listed model is still read with the user's access rights, and a read-only key still cannot write to a model you opened for writing.

One list per database

The list holds for every key and every company; a domain on user or company_ids tells them apart.

Agent files stay readable

Files that belong to no record, and the files a module hands to the agent itself, are not held back by the list.

Requirements

Odoo.sh or on-premise, Community or Enterprise, and MuK MCP Server. No extra Python packages.

Configuration

Settings  ›  MCP  ›  Authentication  ›  Access holds the list, for administrators. The MCP Server block in the general settings links to it.

Installation

Depends on muk_mcp. Install it like any other module; nothing changes until the first model is listed.

Usage

Add the models with Add Models, switch on writing where the agent should change data, and add a record domain where it should see only part of a model.

Upgrade

The entries are records, and an upgrade keeps them with their permissions and domains.

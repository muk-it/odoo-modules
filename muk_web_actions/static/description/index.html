What it adds

The menus you know, run in slices

Nothing new to learn for the people who click. You flag an action or a report once, and from then on it runs in batches from the list, the kanban and the form.

Your batch size

Each server action sets how many records go to the server per request, one hundred unless you change it.

Select all, really all

With the whole domain selected, the ids are resolved on the server first and then sent in batches like any other selection.

A failure stops, it does not undo

Each batch commits on its own. If one fails, the run stops with the error and the batches before it stay saved.

Standard until you flag it

Actions and reports without Execute in Batch behave exactly as they do in standard Odoo.

Server actions

Two fields, next to the model

Turn on Execute in Batch on any server action in the Actions menu of its model and set the Batch Size. Run it on 640 contacts with a size of fifty and the server sees thirteen short requests instead of one long one — each small enough to finish well inside the timeout.

Reports

One PDF per record

Select twenty quotations, pick the report from the Print menu, and you get twenty files named after their orders — ready to file or send one by one, instead of a single document you have to split by hand.

Files, not pages

The toggle is offered on PDF and text reports. An HTML report opens in the browser, so it has none.

Requirements

Odoo.sh or on-premise, Community or Enterprise.

Configuration

In debug mode, turn on Execute in Batch on a server action or a PDF report that is in the Actions or Print menu of its model.

Installation

Depends on muk_web_utils for the progress bar, nothing external.

Usage

Select records in a list, a kanban or a form and pick the action or report as usual; the progress bar does the rest.

Upgrade

The flags are fields on the actions and reports, so they carry over with the database.

Overview

MuK AI Chatter puts the agents of muk_ai where the work already happens. Type @ in a Discuss channel or a direct chat, pick an agent the way you pick a colleague, and the answer comes back in that same conversation. On a record, the Write with AI panel drafts the message for you and shows exactly what it would change before a word of it reaches the composer. Every run stays attached to the record it was started from, listed in its chatter. Plugs into muk_ai via _inherit only — no fork.

Mention an Agent in a Conversation

Every agent is given a stand-in contact with no email address, so Odoo's own mention machinery carries it: the chip, the paste rules and the recipient handling are all stock. Discuss suggests members only and admits nobody else as a recipient of a chat, so the agents are named back into both lists — offered next to the members and carried through the post, without ever joining the conversation. A message from the agent appears straight away and is rewritten in place with the answer as the run finishes; everybody watching sees it swap over without reloading.

Write with AI

The chatter composer carries a Write with AI button, and every rich-text editor the same command in its toolbar and behind /. What the panel offers depends on what is in the composer: with text selected, the transforms that rewrite exactly that part — shorten, expand, formal, friendly, fix grammar, translate — shown as a diff against what was selected; on an empty composer, what can be written from the record, with a length and a tone chosen before generating. The answer streams in as it is written, and nothing reaches the message until Insert or Replace is clicked. Esc dismisses at no cost.

The Chips Are Records, Not Code

Every offer in the panel is a muk_ai.skill of type Composer, edited under MuK AI → Skills. Each one carries its wording, its icon and the category that decides where it is offered — fix, rewrite and transform act on what is already written, generate writes something new. Retune the tone for a customer, add a chip in the language your team writes in, or drop one you never use. A composer skill is offered here and nowhere else: it never joins the list of skills an agent discovers in a chat.

When a request outgrows a chip, Open in AI chat hands the very same session — draft, selection and conversation included — to the chat window, where the agent can ask questions again.

Every Run Stays with Its Record

Sessions carry the business record they were started for, so the AI Sessions box in the chatter lists the runs held against it, live over the bus, and one click opens the chat where it happened. Pinning a run to a record grants nobody anything: a conversation gathers tool output under one user's rights, so it stays with the user who ran it — an administrator sees the lot. The same chats are collected in the Records space of the AI sidebar.

Built for an Untrusted Thread

A mention points a language model at a thread largely written by people outside the company — inbound customer mail is the most attacker-controlled text an Odoo database holds. So the conversation is passed as data inside a <thread_context> block it cannot break out of, the tool set is fixed before the agent reads any of it, and the thread is snapshotted onto the session because chatter messages can be edited after the fact. An agent's own post summons nobody, so agents cannot answer each other in a loop. Agent contacts are stripped from the recipients of every message, so naming one never mails it, notifies it or enrols it as a follower. A poster who may not run a session — a portal customer on their own order — summons nothing, and their message posts as usual. The writing helper runs read-only whatever it is asked for. Answer Mentions per agent is the off switch.

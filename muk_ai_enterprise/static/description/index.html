Borrow Enterprise AI tools, RAG sources and record context in MuK AI sessions

Enterprise Builds on MuK AI

Overview

A one-way bridge between MuK AI and the Odoo Enterprise AI stack. The Enterprise side is never modified — the Discuss ai_chat channels, the systray, chatter and composer buttons, the ai.agent replies, LLMApiService and the ai_fields cron all keep their existing behaviour. Both chat clients coexist side by side; no monkey-patches, no record-rule rewrites, no shadow data.

What you get is the freedom to compose: keep using Enterprise AI for chatter assistance and field auto-fill, and pick up MuK AI for the agentic chat, multimodal attachments, the MCP-driven tool surface, the session approval gate, the audit log and the multi-provider runtime — while still re-using the AI tools, RAG sources and per-record context you already configured on the EE side.

Plays nicely with every optional ai_* satellite shipped by Enterprise — ai_documents, ai_livechat, ai_fields, ai_server_actions, ai_knowledge, ai_website, ai_crm — without adding any of them as a hard dependency.

Borrow Enterprise Tools (Server Actions)

Pick one or more ai.topic records on a MuK AI agent's new Enterprise tab. Every server action bundled in those topics — the same ones the EE ai.agent would call — is exposed in the MuK AI session as an ee_action_* tool. The model sees a normal MCP-style tool descriptor, calls it with JSON arguments, and the bridge dispatches the underlying ir.actions.server with the appropriate context.

Borrowed tools flow through the exact same governance as native MuK AI tools: per-agent tool filter, read-only scope enforcement, the session-scoped approval gate (one-shot, allow-for-session, or reject), and the JSON-serialised tool log under MuK AI > Reports > Approval Log and the muk_mcp tool log. Your EE-side audit trail keeps working untouched on the Enterprise side.

Borrow Enterprise RAG Sources

Pick one or more ai.agent.source records on the agent's Enterprise tab. On every user message the bridge resolves the EE provider, embeds the user query with the same embedding model the EE agent would use (defaulting to text-embedding-3-small at 1536 dims), retrieves the top-N similar ai.embedding chunks across the picked sources, and appends them to the rendered system prompt inside a <rag>...</rag> block.

The retrieval call is sudo-scoped (so the bridge can read the embedding rows) but the chunks are attached to the system prompt of the calling user's session — record rules on the underlying source data still gate what makes it into ai.embedding in the first place. Failures degrade gracefully: missing provider, no embedding back, no chunks — the prompt simply renders without the RAG block.

Per-Record Context Bridge

When a MuK AI chat opens with a record in view context (form view, kanban card, list selection — any of the MuK AI view_context entry points), the bridge calls Enterprise's Model._ai_initialise_context hook on the pinned record and injects the result inside an <ee_ctx>...</ee_ctx> block on the system prompt.

That means an EE-aware model (an ir.model with _ai_initialise_context implemented for Sales Orders, Invoices, Tasks, Tickets, etc.) shares the same per-record briefing with both the EE chatter assistant and the MuK AI floating chat — users never have to re-explain "this order" or "the current invoice". The normal MuK AI <ui_ctx> tag (model, id, view kind) keeps shipping alongside.

Configuration

  1. Install muk_ai_enterprise — pulls in muk_ai and ai.
  2. Open MuK AI > Configuration > Agents and edit the agent that should borrow EE assets.
  3. On the new Enterprise tab, pick the ai.topic records whose server actions you want exposed.
  4. Pick the ai.agent.source records whose RAG chunks you want injected.
  5. Optionally pin a model with enough context headroom to absorb the appended <rag> and <ee_ctx> blocks.

That's the entire setup — per-record context is wired automatically once the chat opens with a record in view context. Both EE features (Discuss ai_chat, ai.agent, chatter assistance) and the MuK AI suite continue to operate independently.

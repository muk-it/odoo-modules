Where you work

One chat, on every screen

The chat is a page of its own and a window beside any form or list. Both show the same conversation, so a question started on a record can end on the full page without losing a word.

A window beside any record

The robot in the top bar opens a chat that knows the record or list you are on. Expand it, and the draft and its files come along.

Spaces and sharing

File chats into spaces, each with its own default agent, and share a chat with colleagues who may read every step but not steer it.

Files in, sources out

Attach images, PDFs or text to a question. Every answer lists the records and pages it was built from, one click from each.

Rewind, branch, search

Rewind a chat to any message, branch it into a new one, regenerate the last answer, or search the conversation for a word.

Context and cost in view

A ring under the chat bar shows how full the context is and what the last turn cost. A full chat compacts itself and goes on.

Limits you set

Cap the rounds, the run time and the money one turn may spend, and the chats a user may start in a minute.

In the view

Ask the list, and it changes

Ask for a filter, a grouping or a chart, and the list, kanban, pivot or graph in front of you changes in place. The agent drives Odoo's own search in your browser tab, so what it set stays in the search bar for you to keep or remove.

On a form, the window knows the record, so “this order” or “this customer” needs no explaining, and a record the agent opens for you becomes the new context.

Approvals

It asks before it writes

Mark a model as sensitive, and every create, change, delete or method call an agent wants on it waits for you. The card names the record and shows each field as it is and as it would become.

Reject it, and the agent hears why and looks for another way. Every decision goes into the approval log with what was asked and what ran.

For this chat only

Allow for session lets the same kind of call through until the chat ends. The next chat starts with nothing allowed.

Agents

An agent for each kind of work

An agent holds the instructions, the provider and model, how hard the model thinks, the tools it may call, and whether it may search the web, draw images or run code. A general assistant comes with the module.

An agent can hand the chat to another agent that fits. Read-only is enforced by the server, not asked of the model, and every change to the instructions can be rolled back from the prompt history.

Where it stops

Built to be extended

The assistant is the base the other MuK AI modules build on, and the same seams are open to a module of yours — behind the same agents, approvals and access rights.

A provider in one file

Subclass ProviderBase and register it, and the provider shows up in the settings, on the agents and in the model catalogue.

Tools from your modules

A tool your module adds to muk_mcp is there for the agents at once, with the same access rights; one registry keeps a tool for the agents alone.

Tools in the browser

A tool can run in the user's tab instead of on the server, the way the view reshaping does. Register yours in muk_ai.client_tools.

Requirements

Odoo.sh or on-premise, Community or Enterprise, and an API key from OpenAI, Anthropic or Google. On Enterprise it runs beside Odoo's own AI apps, with its own icon and its own chats.

Configuration

Paste the key under MuK AI  ›  Configuration  ›  Providers, set defaults and limits in the settings, then shape the agents and mark the sensitive models.

Installation

Depends on mail, bus, base_setup and muk_mcp. Install it like any other module; the providers, their models and a general assistant are there at once.

Usage

Open MuK AI  ›  Chat, or the robot in the top bar on any screen, and ask. Answer an approval card when the agent wants to change a sensitive record.

Upgrade

Chats, spaces, agents and providers are records, and an upgrade keeps them, keys and space icons included.

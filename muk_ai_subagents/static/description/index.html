Overview

MuK AI Subagents lets an agent hand a focused task to another agent and carry on. Each subagent is a session of its own, with its own context and its own agent configuration, so the permission model is the one you already know.

A single agent asked which of your top thirty resellers are trending down this quarter has to read thirty accounts into one context window and keep them all straight. Three subagents each reading ten, and reporting a short summary back, is both faster and more accurate — each one starts clean.

The rule the module is built around: parallelise reads, serialise writes. Fan-out wins on breadth-first reading and loses on work that has to compose into a single artifact. Delegation is offered for the first and capped so it cannot quietly become the second.

One Line, Always in View

A run is watched from a single line above the composer: a dot per subagent and the one thing worth knowing right now — how many are working, who has been waiting on you and for how long, or that one has started repeating itself. It says nothing at rest and it never covers the conversation.

Open it and the roster drops down, ordered by what needs you first: waiting on you, stopped early, working, done. Finished rows stay while anything still runs, then fold into a counted group; a row that failed never folds.

Look Closer Without Losing Your Place

Opening a subagent’s row opens its detail under it, in place: the full activity line, the question if it is blocked, its last few actions, its own cost, and buttons to open its transcript or stop it. Nothing floats over the conversation and nothing moves.

Every Subagent Is Openable

Opening a subagent goes to it, the way you go to any other conversation: it takes the room the chat had, with a breadcrumb back. One composer writes to whichever conversation is on screen and says whose it is. The same move works on the full page, in the floating window and on a phone. Every run keeps a permanent link, so a subagent is still readable long after it finished.

Subagent tool calls never stream into the parent conversation. What arrives there is one card per subagent: name, duration, cost, its one-line answer, and a link to the full transcript.

It Asks Where You Are Looking

A subagent that needs an approval or an answer would otherwise pause where nobody can see it. Instead the question is raised in the conversation you are actually in, named and coloured, with the buttons you already know: Approve once, Allow for session for that subagent only, and Reject — which hands the refusal back so the subagent re-plans instead of ending the run.

A subagent’s permissions are the intersection with the conversation that spawned it, never the union. And no message from any agent counts as a human approval.

Not Getting Stuck

Repeating itself is the most common way a delegated agent fails, so the runtime watches for it rather than trusting the prompt. Each action is fingerprinted as the tool, its arguments and a hash of its result: the same action with the same result three times is a loop, while the same action with changing results is ordinary work and is left alone.

When it fires, the subagent is first told plainly that it is repeating itself, then loses that tool for a couple of rounds, and only then is stopped — and it is flagged on its row while it still has rounds left, not only in the post-mortem.

Every ending is labelled: finished, out of budget, no progress, hit the round limit, stalled, stopped by you. Anything that is not a clean finish is shown as a warning on the result card, because a summary that quietly omits how much it did not get through is the most dangerous thing this module could produce.

Limits

Five subagents at once per run, and one level deep — a subagent cannot delegate further. At the limit the tool is simply not offered, rather than offered and refused. The per-run budget covers the whole tree, and a subagent’s deadline never outlives its parent’s.

Subagent sessions stay out of the way: they are absent from the chat sidebar, raise no unread counts, and are collected in a Subagents space of their own.
